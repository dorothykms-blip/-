# 택시타쉐어 MVP 스프린트 개발 계획

> 기준 문서: `PRD.md`, `AGENTS.md`, `docs/agent-prd-contract.md`  
> 상태 표기: `[ ] 미착수` · `[-] 진행 중` · `[x] 완료` · `[!] 차단됨`  
> 이 문서는 스프린트 종료 때마다 체크박스, 증적, 잔여 이슈를 갱신한다.

## 운영 방법

1. 작업을 시작할 때 해당 항목을 `[-]`로 바꾸고 담당자·시작일을 기록한다.
2. 작업 PR/커밋, 테스트 결과, 화면 캡처 또는 배포 URL을 **증적**에 남긴다.
3. 완료 조건이 모두 충족됐을 때만 `[x]`로 바꾼다. 외부 결정이 필요한 경우 `[!]`와 차단 사유를 기록한다.
4. 스프린트 종료 시 `진척 현황`, `결정 기록`, `다음 스프린트 준비`를 반드시 갱신한다.
5. 새 요구사항은 현재 스프린트에 무단 삽입하지 말고, `변경 요청`에 추가한 뒤 우선순위를 결정한다.

## 전체 의존성

```text
S0 기반/결정
  └─ S1 가입·세션
      └─ S2 모집·지도·예상요금
          └─ S3 참여·추천·모집마감
              └─ S4 포인트 원장·예치·취소/노쇼
                  └─ S5 실제요금·이의·최종정산
                      └─ S6 운영·안전·알림·출시
```

## S0 — 기술 기반과 운영 결정

**목표:** mock UI 기반 프로젝트를 실제 MVP 구현이 가능한 서버·데이터·환경 기반으로 전환한다.  
**PRD:** TR-06, TR-07, TR-08, 데이터 모델 초안, 오픈 이슈 1·4·6·8  
**스킬/에이전트:** `prd-feature-delivery`, `vercel-release-readiness`, `map-provider-adapter`; `vercel_release_guardian`, `map_provider_architect`

- [ ] Neon 프로젝트/리전, 연결 방식, 개발·프리뷰·운영 DB 분리 기준을 결정한다.
- [ ] ORM 또는 SQL 접근 방식을 결정하고 마이그레이션 실행 절차와 롤백 원칙을 문서화한다.
- [ ] 사용자, 모집, 참여, 예상요금, 정산, 포인트 원장, 신고의 초기 스키마와 인덱스·제약 조건을 작성한다.
- [ ] 비밀값 계약을 정의한다: DB 연결, 지도 제공자 키, 앱 URL, 인증 관련 값. 실제 값은 저장소에 넣지 않는다.
- [ ] Vercel Development/Preview/Production 환경 변수와 배포 흐름을 설정한다.
- [ ] 네이버 지도와 카카오맵 중 첫 제공자를 결정하거나, 어댑터 인터페이스와 선택 기준을 확정한다.
- [ ] 관리자 권한 부여 방식과 초기 포인트 지급 정책을 결정한다.
- [ ] 백업·복구·오류 모니터링의 최소 운영 절차를 정의한다.
- [ ] `npm run build`가 통과하고 Preview 환경에서 기본 앱이 동작한다.

**완료 조건:** 실제 DB에 안전하게 연결할 수 있고, 환경별 비밀값·마이그레이션·지도 제공자 선택이 문서화되어 있다.

## S1 — 가입, 세션, 프로필 완성도

**목표:** 필수 정보가 있는 사용자만 핵심 기능에 진입하도록 만든다.  
**PRD:** FR-01 ~ FR-04  
**스킬/에이전트:** `prd-feature-delivery`, `privacy-safety-moderation`, `mobile-flow-quality`; `nextjs_mobile_builder`

- [ ] 학번·이름·성별·학교 이메일 필수 입력과 서버 측 유효성 검증을 구현한다.
- [ ] MVP 범위대로 별도 전화·이메일·학생증 인증 없이 가입을 완료한다.
- [ ] 사용자 레코드와 세션/식별 방식을 구현한다.
- [ ] 필수 프로필 미완료 사용자의 방 생성·참여를 서버와 UI에서 차단한다.
- [ ] 개인정보 수집 목적·보관·삭제 정책을 가입 화면 또는 연결된 정책 화면에서 고지한다.
- [ ] 모바일 폼의 입력 오류, 제출 중, 서버 오류, 재진입 흐름을 검증한다.
- [ ] 개인 정보가 로그·분석 이벤트·클라이언트 콘솔에 노출되지 않는지 확인한다.

**완료 조건:** 새 사용자가 가입 후 핵심 기능에 진입하고, 미완료 사용자는 우회할 수 없다.

## S2 — 방 생성, 지도 검색, 예상 요금

**목표:** 사용자가 지도 근거가 있는 출발·도착 정보와 예상 분담금으로 방을 만들 수 있다.  
**PRD:** FR-10 ~ FR-17, FR-32, TR-08  
**스킬/에이전트:** `map-provider-adapter`, `room-state-machine`, `mobile-flow-quality`; `map_provider_architect`

- [ ] 지도 장소 검색과 현재 위치 사용 동의 흐름을 구현한다.
- [ ] 제공자 중립 `MapProvider` 어댑터를 만들고 장소·거리·시간·예상요금 결과를 정규화한다.
- [ ] 경로 계산 실패/키 누락/지원하지 않는 장소에 대한 안전한 오류 UI를 만든다.
- [ ] 방 생성 시 출발지, 도착지, 출발 시각, 목표 인원(2–4), 승인 방식, 예상요금을 서버에서 검증·저장한다.
- [ ] 예상 총요금과 목표 인원 기반 1인 예치 예정액을 구분해 표시한다.
- [ ] 자동 마감 시각과 방장의 수동 마감·전체 취소 진입점을 구현한다.
- [ ] 지도 제공자 결과·산정 시각·요금 근거가 추적 가능하게 저장되는지 확인한다.

**완료 조건:** 실제 지도 API 근거가 없으면 요금을 표시하지 않으며, 유효한 방은 `OPEN` 상태로 생성된다.

## S3 — 참여, 매칭 추천, 모집 마감

**목표:** 사용자가 열린 방을 탐색·신청하고, 설명 가능한 추천을 통해 참여할 수 있다.  
**PRD:** FR-18 ~ FR-26, TR-04, TR-05  
**스킬/에이전트:** `room-state-machine`, `matching-recommendation`, `mobile-flow-quality`; `map_provider_architect`

- [ ] 열린 방 목록과 방 상세에 출발/도착 지역, 시각, 현재/최대 인원, 예상 분담금, 상태를 표시한다.
- [ ] `OPEN` 방에만 참여 신청을 허용하고, 중복 신청·정원 초과·마감 후 신청을 서버에서 거절한다.
- [ ] 자동 승인과 수동 승인 흐름을 구현하고, 승인 권한을 방장으로 제한한다.
- [ ] 출발 시각 자동 마감과 수동 마감 후 최소 인원 기준으로 `CONFIRMED` 또는 `EXPIRED` 전이를 구현한다.
- [ ] 동일/인접 목적지, 출발지 근접도, 시간, 잔여 좌석을 기반으로 후보를 만든다.
- [ ] 인접 목적지 허용 반경·숨기기 옵션을 반영하고, 추천 카드에 근거·거리·사유·산정 시각을 표시한다.
- [ ] 추천이 자동 참여·자동 확정을 절대 수행하지 않는지 검증한다.

**완료 조건:** 정원·상태·권한 경쟁 조건을 포함해 참여와 마감이 일관되게 동작한다.

## S4 — 포인트 원장, 예치, 취소와 노쇼

**목표:** 실제 화폐 없이 관리자 지급 포인트로 예치와 예외 처리까지 안전하게 수행한다.  
**PRD:** FR-30 ~ FR-40, 취소·노쇼 정책, TR-01 ~ TR-03  
**스킬/에이전트:** `point-ledger-settlement`, `room-state-machine`; `neon_ledger_guardian`

- [ ] 관리자만 대상·금액·사유를 지정해 포인트를 지급할 수 있게 한다.
- [ ] 지급 관리자, 대상, 금액, 사유, 시각을 포함하는 원장 기록을 남긴다.
- [ ] 참여 확정 시 예상 분담금을 일반 잔액과 분리된 예치금으로 처리한다.
- [ ] 부족 잔액, 중복 요청, 동시 요청을 서버 검증·트랜잭션·멱등성 키로 처리한다.
- [ ] 방 취소, 참여 취소, 최소 인원 미달, 노쇼 시 PRD 정책에 맞는 반환/보류/차감 경로를 구현한다.
- [ ] 원장 기반 거래 내역과 현재 사용 가능 포인트·예치 포인트를 표시한다.
- [ ] 중복 예치·중복 반환·상태 역전이 발생하지 않는지 검증한다.

**완료 조건:** 잔액은 원장으로 재현 가능하고, 어떤 재시도도 중복 금액 이동을 만들지 않는다.

## S5 — 실제 요금 확인과 최종 정산

**목표:** 실제 택시비 입력부터 이의 제기, 차액 반환/추가 차감, 거래 내역 표시까지 완결한다.  
**PRD:** FR-35 ~ FR-40, FR-50 ~ FR-55, TR-01 ~ TR-03  
**스킬/에이전트:** `point-ledger-settlement`, `room-state-machine`, `privacy-safety-moderation`; `neon_ledger_guardian`

- [ ] 모집자 또는 지정 참여자만 실제 총요금을 입력할 수 있게 한다.
- [ ] 영수증 첨부를 지원할 경우 파일 검증·접근 통제·보존 정책을 적용한다.
- [ ] 참여자의 동의·이의 제기와 이의 제기 기한을 상태로 관리한다.
- [ ] 전원 동의 또는 기한 만료 전에는 최종 정산을 실행하지 않는다.
- [ ] 실제 총요금을 정산 대상 인원으로 나누고, 예치 초과분 반환·부족분 추가 차감을 원장으로 처리한다.
- [ ] 포인트 부족 시 관리자 지급 요청 및 지급 후 재시도 흐름을 구현한다.
- [ ] 완료 후 개인별 분담 결과와 거래 내역을 표시한다.
- [ ] 정산 실행 재시도·동시 실행·이의 제기 중 실행을 검증한다.

**완료 조건:** 실제요금 확인부터 정산 완료까지 모든 금액 변동이 한 번만 원장에 기록된다.

## S6 — 운영, 안전, 알림, 파일럿 출시

**목표:** 운영자가 MVP를 안전하게 운영하고, 파일럿 출시 기준을 충족한다.  
**PRD:** FR-05, FR-26, FR-51, FR-55, 비기능 요구사항, 출시 승인 기준  
**스킬/에이전트:** `privacy-safety-moderation`, `vercel-release-readiness`, `prd-acceptance-review`; `vercel_release_guardian`

- [ ] 신고·차단 접수, 운영자 처리 상태, 최소 운영 대응 절차를 구현한다.
- [ ] 참여 승인, 예치 요청, 모집 마감, 집결 임박, 정산 요청/완료 알림을 구현하거나 MVP 대체 채널을 명시한다.
- [ ] 확정 참여자만 접근 가능한 그룹 채팅 또는 명시적 대체 방식을 결정한다.
- [ ] 장애·백업·복구·배포 롤백 절차를 테스트 또는 리허설한다.
- [ ] Vercel Preview에서 가입 → 방 생성 → 참여 → 예치 → 정산 전체 흐름을 검증한다.
- [ ] 개인정보·위치정보·포인트 정책에 대한 법률/운영 검토의 책임자와 완료 상태를 기록한다.
- [ ] PRD 출시 승인 기준을 `prd-acceptance-review`로 점검하고 미충족 항목을 차단 목록으로 관리한다.
- [ ] 파일럿 캠퍼스, 운영 시간, 지원 채널, 장애 연락 체계를 확정한다.

**완료 조건:** 출시 승인 기준의 Must 항목이 검증되고, 운영·보안·복구의 담당자와 절차가 준비되어 있다.
